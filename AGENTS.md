# AI Agent & Developer Guidelines (`AGENTS.md`)

This document serves as the authoritative guide for AI coding agents (Antigravity, Gemini, GitHub Copilot) and developers modifying or extending the **gladCode 2** repository.

Layer-by-layer project skills (API, models, MySQL, frontend, CSS, tests, docs, simulation) live in [`.agents/skills/`](.agents/skills/README.md); load the one for the layer you touch.

---

## ⛔ CRITICAL EXECUTION RULES

> [!CAUTION]
> **NO LOCAL PYTHON OR NODE ON HOST ENVIRONMENT**
> The host machine does **not** have Python or Node.js installed natively.
> - **NEVER** run commands like `npm run dev`, `node app.js`, `python3 script.py`, or `pip install` directly on the host shell.
> - **ALWAYS** execute Node, Python, C compilation, database operations, or scripts via **Docker** / **Docker Compose** containers:
>   - API: `docker compose exec api sh` (tests: `docker compose exec -T api npx vitest run`)
>   - Web: `docker compose exec web sh`
>   - Runner: `docker compose exec runner sh`
>   - MySQL: `docker compose exec mysql mysql -u root -p`
>   - Repository tooling (lint, frontend tests, generators): `docker run --rm -v "$PWD":/w -w /w node:22-alpine ...`
>   - Container control: `docker compose up -d`, `docker compose restart <service>`

## 🏛️ System Architecture

gladCode 2 runs as Docker Compose services:

```
Browser ──> [web: Express + Mustache]   page shells, static files (web/)
   │
   └──────> [api: Express REST API] ──> [MySQL 8.0]
                   │  (writes data/runs/<dir>, then HTTP POST /:dirname)
                   ▼
            [runner: Express] ──> [gladcode2-vm container (host Docker)]
                                          │
                                          ▼
                              [C engine (gladCodeServerMain)]
                                   ├── code0.c / code0.py (Gladiator 1)
                                   └── code1.c / code1.py (Gladiator 2)
```

The browser loads page shells from `web` and talks to `api` directly (`API_URL:API_PORT`, cookies included). The web service never sees the session. Battle logs, run folders and profile pictures live under `data/` on the host.

## 📂 Subsystem Breakdown & Key Files

### 1. API (`api/`)
Express 4 REST API built like node-aec: `app.js` wires middleware and routers; `route/` composes HTTP (one router per area, every route documented with a `METHOD /path` comment, input checked with `helpers/validation.js` `Validate`, handlers wrapped in `asyncRoute`); `model/` owns persistence and rules (classes, many on the base `Model`); `helpers/` holds the rest; `middleware/` has `auth()` and the error handler. The endpoint reference is generated into [`docs/api/README.md`](docs/api/README.md) by `api/scripts/api-docs.js`.

- **Sessions**: Google sign-in (`POST /auth/google`) issues the `app_session` HttpOnly cookie, a JWT signed with `JWT_SECRET` (`helpers/jwt.js`). `auth()` requires it, `auth({ optional: true })` reads it when present, `auth({ admin: true })` also requires an email listed in `ADMIN_EMAILS`. CORS allows only `WEB_URL:WEB_PORT`, and cookie requests that change data must come from that origin (`helpers/platform.js`).
- **Errors**: throw `CustomError(status, message, code, data)` (`helpers/error.js`); the error middleware answers `{ error, status, type, code, message, data }`. Clients branch on `code`.
- **Database**: `helpers/mysql.js` `Mysql` is the only SQL executor (`find`, `findOne`, `count`, `insert`, `update`, `delete`, `select` for parameterised reads, `withTransaction`, `raw` for trusted SQL fragments, `contains` for LIKE values). Only models call it. Lock rows with `SELECT ... FOR UPDATE` inside `withTransaction` when two requests could race (team changes, group battles, potion purchases).
- **Battles**: `model/battle.js` `Battle` builds a run folder in `data/runs/<dir>` (Payload files plus each gladiator's code, `helpers/gladiator-code.js` prepares sources and setup blocks), calls the runner (`helpers/runner.js`) and stores the log (`model/battle-log.js`: a `logs` row plus the JSON file in `data/logs/<id>`). Editor tests (`POST /battles/test`) run in the sandbox; ranked (`model/ranked-battle.js`), duel (`model/duel.js`), tournament (`model/tournament-round.js`) and training (`model/training-round.js`) battles do not. Tournament battles send `noitems`.
- **Battle results**: `helpers/battle-results.js` holds the pure rules (renown `calcReward`, `masterRewards`, `crashedGladiators`, `survival`/`placingOrder` for group battles, `trainingScores`), covered by `tests/unit/helpers/battle-results.test.js` with golden values from the old PHP code. Battles that count are judged by the engine simlog alone: a gladiator whose client crashes mid-battle is killed by the engine and marked `"crashed":1`, and ranked battles flag it `version = 'broken'`. Never blame gladiators from `errorc.txt` text, which every gladiator can write to.
- **`banned_functions.json`**: Security policy listing forbidden C function names (`setPosition`, `setHp`, `setAp`, `lvlUp`, `mudaPosicao`, `mudaPv`, `mudaPh`, `sobeNivel`), checked when gladiators are saved. The engine enforces the same rule: these sandbox commands (and `-1` "any item" potion slots) only work in editor test battles (`Battle` with `sandbox: true`). Tournament battles use `noitems: true` instead: the runner appends `noitems` to `socket_compile.sh`, the engine's `setSlots` then drops every slot (user code cannot re-enable it) and the setup sends empty `setSlots("0,0,0,0")`, so potions never work in tournaments.
- **Version**: `api/version` is the engine version; gladiators saved on another one are outdated. Bump it in a commit (`chore(release): ...`); the update page (`/update`, administrators) carries older gladiators forward and emails the release.
- **Mail**: `helpers/email.js` `sendMail(template, ...)` fills `templates/mail/mail_<name>.html` (values escaped unless listed in `raw`) and sends through `MAILER_*` SMTP; without `MAILER_USER` it only logs `mail_skipped` (use that locally: `MAILER_USER= docker compose up -d api`).
- **Scripts** (`api/scripts/`, run with `docker compose exec -T api node scripts/<name>.js`): `issue-session.js <userId>` (development sign-in cookie), `battle.js <id> <id> [--keep]` (a battle between any saved gladiators outside the game modes, for triage), `dev-tournament.js` (tournament dev tools, wrapped by `dev-tools/tournament.sh`), `remove-old-battles.js [--dry-run]` (cron: expires old editor and ranked logs), `api-docs.js` (regenerates `docs/api/README.md`; run it from the repo root through `node:22-alpine`).
- **Tests**: Vitest and supertest in `api/tests/unit/` (`docker compose exec -T api npx vitest run`); models are tested with a mocked `Mysql`.

### 2. Web (`web/`)
Express service rendering Mustache page shells: `app.js` declares every page with `page(route, view, clientVars)`, `middleware/render.js` adds `res.page()` (header, footer and analytics partials, the `{{#asset}}`/`{{#module}}` lambdas that version files by mtime, the import map, and `{{{templateVars}}}`, the JSON the page script reads through `helpers/template-var.js`), `view/*.html` are the pages, `public/` the static files. Old addresses, with or without `.php` (and `/editor?g=`), redirect permanently (`helpers/urls.js`; the catch-all `/:page` redirect runs after every page route, so a page `legacyPageUrl` maps to must be registered before it). `scripts/compress-functions.js` rebuilds `public/script/functions.json` and the sample bundles after the API reference (`public/script/functions/`) changes.

- **Frontend JavaScript (`web/public/script/`)**: native ES modules, no jQuery. Layout follows node-aec: page entries in `script/*.js`; `helpers/` (non-DOM utilities: `request.js` fetch transport (`api` for the API with credentials and JSON, `site` for same-origin files; failures throw `RequestError` with the API's `code` and `details`), `html.js` `renderTemplate`/`escapeHtml`, `local-data.js`, `template-var.js`, `google-login.js`, `animate.js`, `sprite-catalog.js` + `spritesheet.js`, date and replay helpers); `components/` (DOM classes: `dialog.js` `Message`/`showDialog`/`showInput`/`showTextArea`/`showTerminal`, `toast.js` (its message is markup: escape user text), `tooltip.js` (page-wide `title` tooltips, `.ui-tooltip`), `slider.js` (renders jQuery UI's `.ui-slider` markup, base CSS in `css/ui-slider.css`), `header.js`, `side-menu.js`, `glad-card.js`, `simulation.js`, `countdown.js`); `models/` (the only place that calls the API, one class per area); `templates/` (markup strings: `{{key}}` escaped, `{{{key}}}` raw, no logic); `profile/` and `editor/` hold the profile tabs and the editor parts. `web/helpers/modules.js` versions every module by mtime through one import map that each view prints with `{{{importMap}}}` before any module script; pages load their entry with `{{#module}}page.js{{/module}}`; add new script folders to `MODULE_DIRS`. Vendored libraries (`phaser.js`, `croppie.js`) and the classic Phaser renderer (`render.js`, `floatingText.js`) stay classic scripts. The rules for writing frontend code, and the lint and test commands, are under [Frontend Standards](#frontend-standards).
- **Design system and themes**: [`DESIGN.md`](DESIGN.md) is the direction, [`docs/design-system.md`](docs/design-system.md) the contract. `public/css/tokens.css` holds every colour, font, radius, duration and layer, with three themes mapping the same roles: Arena light (the default on light systems), Arena dark (on dark systems, and `.tone-night` regions) and Classic. Every view includes the `head` partial (font preload, `tokens.css`, the blocking `script/theme-boot.js` that sets `theme-<name>` on `<html>` before paint); masters choose in the profile settings (`usuarios.site_theme`, cached in `localStorage` `gladcode-theme` by `helpers/theme.js`). Stylesheets use tokens only; fonts are self-hosted in `public/fonts/`.
- **`view/playback.html` / `script/playback.js`**: the playback page adds the `script/render2/*.js` versions to its import map (`moduleImports({ render2: true })`, gated by `ENABLE_RENDER2`), so browsers never mix cached and new modules. `playback.js` is the replay module: loading (log download progress, spritesheets), controls, preferences and incremental simlog expansion used by both battle renderers. The classic renderer and render2 share the replay through page globals, so `playback.js` `exposeLegacyGlobals` publishes them on `window` in one place (`steps`, `timestep`, `pausesim`, `stepIncrement`, `hashes`, `newindex`, `uiVars`, `timeSlider`, `fullscreen` as accessors, plus `Playback`, `resize`, `changeCrowd`, `changeSoundIcon`, `getActionName`, `updateDetailedWindow`, `getSpriteThumb`, `images`); keep that list in step with what `render.js` and `render2/` read.
- **`script/render.js`**: Classic Phaser.js 2D battle renderer, a classic (non-module) script that owns `prefs`, `game`, `music`, `json` and the other renderer globals; it uses no jQuery (small `ui*` DOM helpers at its top) and moves the timeline through `window.Playback.syncTimeline`.

the atlases load with three's default `flipY`), Dungeon Realms head props (bandana, afro, pigtails, mohawk, wild and very long hair) hang on the `Head` bone, the `skeleton` body is the Dungeon Realms skeleton bound to the same rig, and weapons, bows and shields come from the Dungeon, Dungeon Realms, Goblin War Camp, Viking Realm and bow packs (`WEAPON_MODELS`, `SHIELD_MODELS`; the shield rides the left forearm and hides while shooting); only the gear the fighters wear is loaded and plays the real Synty clips (`base-locomotion` walk/run/sprint/strafe/back/idle/turn-in-place (the fighter turns at a fixed rate while standing and the 90/180 turn clip follows the angle covered), `sword-combat` attacks/block/hit/stun/death) through an `AnimationMixer` with per-frame weights and times (seek-safe): the clips drive a clean animation skeleton and each bone's world-rotation change from its T-pose is retargeted onto the hero skeleton (the two use different bone axes), weapons sit on the hand at the clips' `Prop_R/L` socket frame, the hit reaction is layered after retargeting (torso/head fully, arms only when no action uses them, legs keep the locomotion), a stunned fighter plays the stun loop with a dizzy wobble layered on top, a hit reaction blends the four directional Synty clips so the body is driven away from the blow (`HIT_SIDES`; an inspected gladiator is framed in one of `INSPECT_MODES`: `fixed` overview, `follow` third person behind it with the wheel setting the distance, `first` through its eyes, cycled with C; `cinematic` circles the victor; a hidden ghost camera, toggled by holding C for 10 s and undocumented in the UI on purpose, flies free over every mode with WASD/arrows, Q/E down and up, Shift faster, any drag to look and Esc to land), canvas-drawn HUD (roster panel with click-to-inspect, hidden with M; below `COMPACT_WIDTH`/`COMPACT_HEIGHT` it switches to compact phone plaques (portrait, name, HP, AP, buffs) in two columns on a narrow screen, and every HUD piece keeps to the safe-area insets read through a probe (`BattleHud#insets`; New arena sounds live in `res/audio/arena/` (Kenney CC0 impacts, OpenGameArt CC0 weapon clashes and coughs, Gregor Quendel CC BY 4.0 crowd; credits in `CREDITS.md` there, keep the credit). `tests/render2/audio.test.mjs` covers the pure parts. Every battle animation runs on the fight's clock (`gameDt`: real time times the replay speed, zero while paused): fighters, Synty clips, sparks, rings, glyphs, blasts, trails, slashes, burning flames and floating combat text; the arena ambience (braziers, crowd, gas, clouds) runs on its own clock that stops while paused and follows the replay speed up to `AMBIENCE_MAX_RATE`, and only the camera and HUD controls use real time. Paused, the scene fades to a moderate grey (`renderer.js` `#renderGrey`: rendered off screen and desaturated on a full-screen pass only while paused or fading, the HUD drawn after in colour). `playback.js` `startTimer` clears any running timer and reads the shared `steps` (a timer started during loading used to pin the replay at its first frame). Timing: each shared-timer frame starts a short interpolation segment from the fighters' current pose; seeks and paused stepping snap. The engine writes its last frames at one simtime and the killing blow can come in a later one, so `renderer.update` skips a repeated frame only when no gladiator's hp, action or level changed (`battle-state.js` `isSameMoment`; the roster plaque also redraws on the alive flag, not only the rounded hp). The last one standing celebrates (`Fighter#setVictor`, crowned by the renderer when exactly one of several gladiators is alive, uncrowned by a rewind): `VICTORY_DELAY` after the final death and then every `VICTORY_CYCLE` it turns to salute a side of the stands (the imperial box first, `VICTORY_SALUTES`), twirls its sword (`A_Idle_Flourish01_Sword`; archers skip it) and raises its weapon high while pumping the other fist, chest out and looking up (`SyntyModel#celebrate`, world-space arm IK in arm lengths), and the crowd rises and cheers each round (`renderer.js` `#cheerVictor`); its buffs and debuffs wear off as it starts (`Fighter#buffs` is empty while celebrating, so flames douse, stars burst, the barrier and invisibility fade). As the celebration begins the camera films the victor in a slow circle, centred on the body and close enough that it fills the laurel ring (height measured from the head bone) (`BattleCameraController#cinematic`, a drag hands it back), golden laurels with the name and master on a ribbon frame it for a few seconds (`PlaybackControls#showVictory`, the overhead cards make way) and the gas clears outward from the safe circle (`#clearGas`); a battle with no survivor shows EMPATE (`battleEnded`, called by playback.js at the last frame instead of the classic victory modal). Actions are paced by the engine (`motion.js` `engineTiming`/`warpedTime`): the engine reports an action id on one step, resolves it after `0.5/as` (attacks) or `0.5/cs` (abilities) and reports "waiting" (9) for the rest of the cycle, so the animation clock is warped to put `contact` on that resolve step (slow fighters hold guard before the wind-up, fast ones shorten it) and to finish the follow-through within the cycle; "waiting" never cancels a running action, each new report restarts it, a block lowers after its cycle, and damage only flinches a victim when it arrives at an attacker's contact (burn/poison ticks just show their number). A fighter hit mid-swing only rocks its torso. Gait phase follows travelled distance, and swings run on a game clock (replay speed scaled, frozen while paused) with damage effects delayed to the swing's contact time. `palette.js` samples the real skin sprite colours (`renderer.prepare()`); Effects use the Synty particle textures (`effects.js` `FX_TEXTURES`: sparkle flares, the block barrier in `fighter.js` (an energy dome around the fighter: fresnel rim, the hexagon texture tiled as a drifting lattice, the barrier strongest ahead of the fighter and fading to a faint minimum at the back, its ground ring an arc round the front only; a ripple from the front when a blow lands, a glowing ground ring), portal vortex and ritual circles for teleport, bubbles for potions). Teleports hold the fighter ~0.5 s while ritual circles light source and target together; speed smoothing (0.3 s) turns walk-stop-walk into a slower continuous walk. `hud.js` composes the whole HUD on canvas from the Synty `fantasy-warrior-hud` sprites (`ART`: 9-sliced gold frames, 3-sliced crystal bars tinted by multiply so bevels keep their light, gem level badge, octagon portrait ring, icons on their underlays; plain shapes stand in while loading or without the pack) with Cinzel titles: roster plaques (team-coloured 3D head shot rendered once by `portrait.js` and converted to sRGB, flat canvas face as fallback; HP/AP/XP gauges, attributes, active buffs), overhead cards that lift apart when they overlap, parchment speech/breakpoint bubbles and gradient combat text; the 3D replay has no DOM controls: `hud-controls.js` `PlaybackControls` draws the control bar (timeline scrubber, settings, fullscreen, step back/forward that always pause first, play/pause, speed −/+ through 0.1× to 10× with a coloured rate and pips, inspect camera mode, sound, share link, shortcuts), a top badge (PAUSADO, or the rate when not 1×) and toasts, the FPS counter (F), the shortcuts window (H) and the inspect window (opens minimized; HP/AP, stats, buffs, items, last commands) on the HUD scene from the same Synty sprites and Font Awesome glyphs, owns the 3D keyboard shortcuts (render.js steps aside), and drives playback through `window.Playback` (playback.js: `setPaused`, `step`, `setSpeed`, `seek`, `toggleSound`, ...); only the settings window is still DOM, and `playback-render2.css` hides the classic bar, FPS and details elements; leaving the browser window or hiding the page (`visibilitychange`, a phone switching apps) pauses, clicks inside never do; the control bar has a one-row `wide` and a two-row `compact` layout (`BAR_LAYOUTS`, larger targets, picked by width), follows the last kind of press (`BattleHud#touch`: on touch no hover tips, pressed buttons light, a taller scrub grip, the bar fades after `CHROME_IDLE_SECONDS` while playing, the share button opens the native share sheet, the shortcuts window shows the gestures), leaves out fullscreen where the browser cannot (iPhone), and the badge, toasts and FPS drop below a roster that reaches across the top; fireball impacts set off a particle explosion (`blast.js`: white flash and a short point light, low-poly fire shards thrown out that slow, rise and cool from white to soot, a dark rolling smoke column, sparks and grit under gravity; four draw calls) and leave scorch marks; an arrow that hits a gladiator (the nearest one, not the archer, within `ARROW_HIT_REACH` of where the engine dropped it) (drawn at `ARROW_SCALE` 0.72, like the nocked one) glides along its line to where it meets the posed body (`SyntyModel#bodyHit`: a raycast on the skinned body meshes, bounds refreshed per call, returning the point and the bone that skins the struck triangle), sinks its whole head in (`ARROW_SINK`) and is bound to that bone so it follows the animation, then after ~2 s drops off, falls flat on the sand and fades (`#stickArrow`); the leader sits on `SyntyColiseum#throne`, his guards on `royal` posts, and `HONOUR_BOX` keeps spectators out), the stands pulled in to `STANDS` 8.75 so the podium wall stands 2.5 m from the curb (gates take three strips: the arch plus wall fillers), eight smaller braziers on the sand in the corner bends (`#braziers`, `BRAZIER_*`: below the front rows' line of sight, clear of the wall and of the combat square), outer gate arches where the roads reach the outer wall, a marble column-and-beam portico crowns the rim, a stone curb marks the 25 m combat square, with lions, statues, banners and weapon racks; the sand floor extends to the podium (`PODIUM`). Beyond the walls `synty-landscape.js` (layout in `landscape-layout.js`, pure and seeded: `landHeight`, `roadDistance`, `footprintDistance`, `planLandscape`; covered by `tests/render2/landscape.test.mjs`) lays out the countryside, loaded after the coliseum and optional: a polar terrain mesh level round the building and rising into hills toward the horizon, its Meadow Forest grass, dry grass and dirt blended by a baked mix while the paved plaza and the cobbled roads (east-west through the gates, north-south past the honour box, winding once in the hills) are traced exactly in the fragment shader (`ROAD_GLSL` must stay in step with `roadOffset`), cypress avenues and a cypress ring round the plaza, fields of straw and crop rows with fences, orchards and wooded hills (only the light tree models past 260 m), carts and a well, farmsteads and a Roman hill town with its temple to the north assembled from Ancient Empire modular pieces (`housePieces`: stucco and window walls on the 2.5 m grid with a door in front, a wall course below ground, `Roof_Base_Peak` tiles turned so the ridge runs along the house, stucco tinted per house through instance colour (`STUCCO_TINTS`); `templePieces`: podium, peristyle, cella, entablature and tiled roof; building textures mapped by FBX material name in `BUILDING_TEXTURES`), POLYGON Mini Fantasy background ranges kept low round the horizon (`MOUNTAINS`), and Synty cloud rings drifting high round the horizon; Ancient Empire pieces load through `synty-arena.js` `loadSyntyKit(THREE, pieces, extraTextures)` (`dungeon:` and `mini:` prefixes for the dungeon and Mini Fantasy packs; placements may carry a `color` tint). `sky.js` is the daylight dome (zenith blue to the `HAZE` horizon, sun disc and glow where the sun light shines from) and the scene fog fades the far hills into the same haze (`FOG_NEAR`/`FOG_FAR`). `renderer.js` `setDebugView({ position, target })` pins the camera anywhere for automated checks, and `getDebugSnapshot().render` reports the scene's draw calls and triangles. `tests/render2/coliseum.test.mjs` keeps the layout off the combat square. The crowd (`synty-crowd.js`, layout in `crowd-layout.js`, loaded after the coliseum and optional) uses the Ancient Empire characters dressed with random hair/beards/helmets/laurels: each type is retargeted from the Synty clips (idle, jump, walk, sheathed-sword idle) with procedural sitting legs and arm IK (clap, fist, wave, pump, arms up), CPU-skinned and baked into a half-float vertex animation texture, then drawn as instanced meshes whose shader reads the frame (`crowdClip`: row, frames, phase, rate). Every build places a fresh random crowd of up to `MAX_SPECTATORS` (800 of the ~4,900 seats; clusters of friends, the front rows filling first and the honour side favoured, heights varied by ±7%), each spectator turning up to `LOOK_LIMIT` off its bench facing to follow the middle of the living fighters (`SyntyCrowd#setFocus`, fed every frame by the renderer), guards only on the structure (gate tops from `SyntyColiseum#posts`, the free front tread, the walkway corners, the honour box), patrols on the front tread and the walkway, benches stopping short of each strip's staircase aisle, motion switches cross-faded in the shader (`crowdFrom`/`crowdSwitch`), and the leader in the honour box; `react()` stands spectators up on deaths, heavy blows and level-ups (a share of `0.05 + 0.65 * intensity²`, so a death raises most of them and a blow only the keenest), the settings crowd slider sets the density, and the gas plane is scaled to the podium; the gas starts exactly at the engine's safe radius (distance from the arena centre, `poison`) with a bright rim on that circle, and `gas.js` adds billowing low-poly poison clouds over the poisoned ground, born only outside the safe radius by their own size and dissolving as they drift toward it. `tests/render2/crowd.test.mjs` covers the layout. Coliseum materials dither out (screen-door discard in `synty-arena.js` `seeThrough`) wherever they stand between the camera and the combat square or right in front of the lens, and the camera pitch stops above the stands. Fires (braziers, gate torches in sconces on the wall face, incense) are `fire.js`: instanced camera-facing particles (`particles.js` `ParticleLayer`, shared with blasts and gas; its `seeThrough` option fades fires that stand between the camera and the combat square) in three draw calls, low-poly flame shards from the particle pack that rise, taper and cool from yellow to red, a breathing glow, smoke and embers; `noise.js` holds the shared seeded noise. Performance: `quality.js` picks a graphics tier per device (`high`/`medium`/`low`: resolution cap, MSAA, crowd share, scenery, floor bake size; phones and small machines start lower; the player can override it in the settings window, stored per device in `localStorage`), and `renderer.js` adapts every 0.7 s: when frames run long it first lowers resolution to 1× if the GPU is the bottleneck, then sheds detail (crowd thinned to 35%, then the scenery hidden via `Arena#setScenery`), then goes below 1×; it decides by the share of the frame its own main-thread work takes (`frame-profiler.js`; the GPU timer query is reported but not trusted, it is emulated on macOS), ignores windows with loading hitches and sheds nothing in the first 12 s. One-time work never lands in the fight: the loading screen stays up until the arena is complete (`Arena#ready`: crowd, floor bake and countryside, at most `WARM_UP_TIMEOUT_MS`), then `#warmUp` compiles every shader in parallel (`compileAsync`, pooled effects shown for it via `BattleEffects#setPoolsVisible`) and draws a frame so every texture is uploaded before `#reveal`; large textures load through `textures.js` `loadTexture` (decoded and flipped into an `ImageBitmap` off the main thread, so the upload is a copy; the Ancient Empire atlases are shared between the coliseum and countryside kits, flagged `userData.shared`, never disposed by a kit, released by `disposeSharedTextures`). Keep the per-frame cost down: the arena floor's terrain splat is baked once into an albedo and a normal map (`synty-floor.js` `bakedMaterial`; the live 20-texture splat was most of the GPU time on Retina screens), the sky draws last at the far plane, static groups are frozen (`freeze` in `arena.js`, `matrixWorldAutoUpdate = false`), the crowd follows the fight at 10 Hz, and Web Audio parameters move through `audio-param.js` `glide` (skips unchanged targets; automation calls every frame were a fifth of the main thread) with the listener at 20 Hz and ambience levels at 10 Hz. `getDebugSnapshot()` reports `timings` (per-section CPU ms, tier, resolution, shed state) and `render` (draw calls, triangles); `setDebugPixelRatio(ratio)` pins the resolution, `setDebugHud(false)` drops the HUD pass for clean captures (how the front page clip `image/home/arena-3d.mp4` and the fighter stills beside it were filmed from a real replay) and `setDebugVisible(name, visible)` hides a named scene part (`synty-crowd`, `synty-landscape`, `synty-scenery`, `synty-coliseum`, `arena-floor`, `fires`, `sky`, ...) to measure what it costs. Materials that flip `transparent` at runtime (invisibility) must set `needsUpdate`, since three compiles an OPAQUE variant. Weapons map per family (`palette.js` `MELEE_KINDS`/`BOW_KINDS`; weapon-pack `oversize_8..27` are five materials in four sizes) to swing specs (`MELEE_STYLES` in `motion.js`) and, per exact token, to Synty models (`synty-outfit.js` `meleeModel`/`bowModel`/`shieldModel`); combat guard stances, strafing and back-pedal gaits live in `motion.js`/`fighter.js`. Unit tests live in `tests/render2/`.
- **`/dev-tools`** (`view/dev-tools.html`, `script/dev-tools.js`): the administrators' tournament cockpit on the `/admin/tournaments` API; `public/dev-tools/synty-viewer.html` is the Synty piece viewer.

### 3. Runner Service (`runner/`)
- **`app.js`**: Express web server listening on port 3000 inside the Docker network (published on the host only by `compose.dev.yaml`). Accepts `POST /:dirname` from the API.
- **Image** (`runner/Dockerfile`): Node plus the Docker CLI, which drives the host's Docker through the mounted socket (no daemon of its own); `production` and `development` (`node --watch`) stages like the API and web services.
- **`runner.js`**: Docker execution manager. Copies the run folder the API prepared from `/requests` (`data/runs` on the host) to the `gladcode_tmp_run` volume, executes `docker run --rm gladcode2-vm sh socket_compile.sh` (appending `sandbox` only when the request body has `sandbox: true`, `noitems` when it has `noitems: true`), enforces the 30-second timeout, reads `errorc.txt` / `simlog`, and cleans up workspaces.

### 4. C Simulation Engine (`Payload/`)
- **`gladCodeServerMain.c`**: Server entrypoint. Creates socket listener, spawns threads per gladiator, tracks turn timeout, and writes `simlog`.
- **`gladCodeServerCore.c`**: Battle logic, damage calculation, movement, turn loop, line-of-sight calculation.
- **`gladCodeAPI.c` / `gladCodeAPI.py`**: Client-side library linked into gladiator code, converting API calls (`stepForward()`, `attack()`) into TCP socket commands to `gladCodeServerMain`.
- **`socket_compile.sh`**: Compilation shell script executed inside `gladcode2-vm`. Compiles user C files (`gcc -o code0 code0.c -lm`) or Python scripts, and launches `gladCodeServerMain <nglad> [sandbox]`. `tests/engine/engine_test.c` unit-tests the engine (Docker command in its header) and `tests/engine/run.sh` runs real regression battles.

### 5. Synty 3D Assets (`web/public/assets/synty/`)
The render2 models, animations and textures come from Synty packs in `web/public/assets/synty/<pack>/` (gitignored, never commit them; production mounts them into the web container from the host). **Whenever you need an asset for the renderer, check `docs/synty-assets/` first**: `README.md` explains units, scale, pivots, material mapping and which loader each pack uses; `INDEX.md` summarises every pack; `<pack>.tsv` lists every FBX with its measured size in metres, pivot, triangles, bones, clips and texture slots (grep it); `<pack>.textures.tsv` lists every image. Regenerate with `docs/synty-assets/build-catalog.mjs` (Docker command in its header) after adding or changing a pack. To see pieces before using them, open `/dev-tools/synty-viewer.html` on the web service (query parameters documented at its top) and screenshot it. Prefer packs and loaders already in use, the Roman `ancient-empire` look round the coliseum, and light models far away; procedural geometry is the last resort.

## 🗄️ Database & Configuration Standards

### Configuration
Every setting comes from the environment (`.env`, passed through `compose.yaml`); there are no config files. `.env.example` lists them: `MYSQL_*`, `JWT_SECRET` (at least 32 random characters in production), `SESSION_TTL_DAYS`, `GOOGLE_CLIENT_ID`, `ADMIN_EMAILS`, `MAILER_*`, `WEB_URL`/`WEB_PORT` and `API_URL`/`API_PORT` (the public URLs), `WEB_PUBLISH`/`API_PUBLISH` (the host ports the containers listen on), `ENABLE_RENDER2`, `MAINTENANCE`, `TRUST_PROXY`, `RUNNER_CONCURRENCY` (battles the engine runs at once, 6; the next ones wait, and editor test battles run one at a time per master or address).

`compose.yaml` runs the production images. For development set `COMPOSE_FILE=compose.yaml:compose.dev.yaml` in `.env`: `compose.dev.yaml` mounts `api/`, `web/` and `runner/` and runs them with `node --watch`, and publishes MySQL (`MYSQL_PORT`) and the runner (`RUNNER_PORT`) on 127.0.0.1. Production publishes only the web and API ports; nothing installs packages at start-up or mounts source there.

### Database Access Pattern
Only models touch the database, through `Mysql` from `api/helpers/mysql.js`, always with placeholders:

```js
import { Mysql } from '../helpers/mysql.js';

const glad = await Mysql.findOne('gladiators', { filter: { cod: id, master: userId } });
const rows = await Mysql.select('SELECT g.cod, u.apelido FROM gladiators g INNER JOIN usuarios u ON u.id = g.master WHERE g.version = ?', [VERSION]);
await Mysql.withTransaction(async context => {
    const [team] = await Mysql.select('SELECT * FROM teams WHERE id = ? FOR UPDATE', [teamId], context);
    await Mysql.update('teams', { modified: Mysql.raw('NOW()') }, { id: teamId }, context);
});
```

Schema changes are numbered SQL files in `migrations/` applied by `migrations/migrate.sh` (the deploy runs it); see the simulation skill's `references/database_migrations.md`. `DATETIME` columns without fractions round `NOW(3)` up, so write `NOW()` when the value is compared right away (deadlines, ends of turns).

## 🔍 Common Issues & Diagnostics

| Symptom | Cause | Solution |
| :--- | :--- | :--- |
| **"CLIENT TIMEOUT"** | Gladiator code stuck in infinite loop without calling API functions or socket stalled | Verify gladiator code contains valid loop calling `gladCodeAPI` actions |
| **Empty `simlog` / `NO_OUTPUT`** | GCC compilation failed for gladiator code or C server | Editor test battles carry the compiler output in `error`; battles that count answer `NO_OUTPUT` and log it as `battle_without_log` (`docker compose logs api`, also printed by `scripts/battle.js`); run the folder by hand (Direct Simulation Debugging) for more |
| **`NOT_SIGNED_IN` (401)** | Missing or expired `app_session` cookie, or a different `JWT_SECRET` | Sign in again; locally use `scripts/issue-session.js` |
| **`CORS_ORIGIN_DENIED` / `CSRF_ORIGIN_DENIED` (403)** | The page's origin is not `WEB_URL:WEB_PORT` | Fix `WEB_URL`/`WEB_PORT` (public URL) in `.env`; host ports are `WEB_PUBLISH`/`API_PUBLISH` |
| **Container Timeout** | Simulation took longer than 30s | Runner kills container via `docker kill {dirname}`. Check for blocking calls or high turn counts |
| **Gladiator `version = 'broken'`, shown as outdated** | Its client crashed (runtime error) during a ranked battle: the engine marked it `"crashed":1` in the simlog and the ranked battle flagged it, removing it from matchmaking | Owner fixes the runtime error and saves the gladiator again to upgrade its version |
| **"ERRO DE SINTAXE" / `NO_OUTPUT` in Matchmaking** | Opponent saved code no longer compiles (runtime crashes no longer fail ranked battles) | Triage candidate pool via pairwise test battles; fix gladiator code or downgrade version |

For detailed guidance on programmatically invoking battles and triaging errors, see [Debugging & Programmatic Battles](.agents/skills/gladcode-simulation/references/debugging_and_programmatic_battles.md).

## 🛡️ Coding Standards & Security Policies

1. **Security Filtering**: Never bypass `banned_functions.json` checks when accepting user C code, and never run counted battles in the sandbox.
2. **Escaping**: Gladiator code and every other text is stored as written; escape it where it is shown (`renderTemplate` `{{key}}`, `escapeHtml`, `textContent`, mail templates fill escaped values). Never put user or server text into HTML unescaped.
3. **Access Checks**: Every API route that reads or changes a master's data uses `auth()` and checks ownership in the model (filter by the user's id); admin tools use `auth({ admin: true })`. Validate every input with `Validate` and keep SQL parameterised.
4. **Races**: Anything two requests could do at once (spending silver, joining a team, running a group battle) runs in `Mysql.withTransaction` with the rows locked first.
5. **Preserve Documentation**: Maintain existing comments, docstrings, and contracts when modifying the API, the web service or C engine source; keep the route comments accurate and regenerate `docs/api/README.md`.
6. **Branches & Commits**: Follow [`CONTRIBUTING.md`](CONTRIBUTING.md): work branches from `dev` named `<type>/<slug>`, Conventional Commits with the scopes listed there, merged into `dev` with `--no-ff`.

### Frontend Standards

Rules for `web/public/script/` (the layout is described under [Web](#2-web-web)):

1. **ES modules only**: new code is a native module with named exports, loaded through the import map (`{{#module}}`), never a classic `<script>`. No jQuery, no new globals on `window` (the replay facade in `playback.js` `exposeLegacyGlobals` is the one exception and only exists for `render.js` and `render2/`).
2. **One job per folder**: page entries only wire a page together; DOM behaviour lives in `components/` classes; pure, DOM-free logic lives in `helpers/` (so it can be unit tested); markup lives in `templates/`.
3. **Network through models**: only `models/` calls the API, through `helpers/request.js` (`api.get`/`post`/`put`/`delete`). Pages and components call model methods, never `fetch` directly, and branch on `RequestError.code`.
4. **Escape by default**: build markup with `renderTemplate` (`{{key}}` is escaped, `{{{key}}}` is raw and only for markup the code built itself) or `textContent`; never put user or server text into `innerHTML`, dialogs or toasts unescaped.
5. **No native dialogs**: never `alert`/`confirm`/`prompt`; use `components/dialog.js` (`showDialog`, `showInput`, `showMessage`) and `components/toast.js` (`createToast`).
6. **No data in the DOM**: keep app data out of `data-*` attributes; map elements to data with a `Map`/`WeakMap` or class fields.
7. **Document what you touch**: JSDoc on exported classes and functions, matching the surrounding code.
8. **Styles from tokens**: colours, fonts, radii, durations and layers come from `public/css/tokens.css` (`var(--color-…)` roles for anything that follows the theme, content tokens for game colours), in CSS, inline styles and JavaScript alike; check pages in Arena light, Arena dark and Classic. The project `css-standards` skill has the details.
9. **Lint and test before committing** (through Docker; the root `package.json` and `eslint.config.js` hold the tooling, `node_modules/` is gitignored):

   ```bash
   docker run --rm -v "$PWD":/w -v /w/node_modules -w /w node:22-alpine sh -c "npm ci && npm run lint && npm test"
   docker compose exec -T api npx vitest run
   docker compose exec -T web npm test        # page routes and old-address redirects
   docker run --rm -v "$PWD":/w -v /w/migrations/node_modules -w /w/migrations node:22-alpine sh -c "npm ci && npm test"   # migration runner
   ```

   `npm run lint` covers `web/` and `api/` and must report no errors: modules get `no-undef`, `no-var`, `no-redeclare`, `no-use-before-define` and `prefer-const`; the classic `render.js` and `floatingText.js` only get the correctness rules until they are rewritten. `npm test` runs `tests/frontend/` and `tests/render2/`; new pure helpers get a test there.
